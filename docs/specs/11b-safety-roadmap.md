## 2. Step A: rest-hours follow-ups and crew authorities
**A1. Crew authorities (the "officer flag").** Today rest hours has one interim rule: only the Master acts as Master (`CrewMember.IsMaster`). Spec 11 says "the Master or someone the Master authorises". The other modules need the same thing: permits (who may issue), drills (who may conduct), incidents (who may investigate onboard). Proposal: one small **authority set** on the crew record, edited in the crew form by a crew admin, next to the flags that exist now (`IsMaster`, `IsCrewAdmin`, `IsRiskReviewer`): sign hours as deputy, issue permits, conduct drills and record meetings, review incidents onboard. The old flags stay; new authorities are added to the set, not as more yes/no columns. A rank can carry default authorities (a company list: "chief officer" gets issue permits and conduct drills). Rest hours changes: the Master's lock and Master signature still belong to the Master; a deputy named in the set may sign **as deputy**, and the record says so. *Why not a role table now:* three or four authorities do not justify a general role system; the set is enough and can grow.
**A2. Retention and the rules page.** `RetentionMonths` exists on the rule set (default 36) but nothing uses it yet: add the check that lists records older than the retention period and are signed (for review, never deleted automatically), and exercise the rules page save, which was opened but not saved in the live check. A vessel's copy of sign-off records is kept; deleting is a decision for the company, so the screen only reports.
**A3. Rest capacity for planned maintenance.** Spec 11 section 7 "later": before a heavy week, PMS jobs due in the next days are set against the rest the crew would have, so a plan that cannot be worked without breaches is seen before it starts. A read-only panel on the PMS board (per department) built from the working table and the jobs' estimated hours; no schedule is changed by it. PMS jobs already carry `EstimatedMinutes` and a `DepartmentId` (checked 2026-11-12), so the panel can be built without changing PMS; what a job lacks is a rank, so the load is shown per department against the departments' crew, not per person.
**A4. Import of existing hours** (spec 11 open question 7): only if you have history to bring (for example from a watchkeeping application); otherwise skipped. A one-off import page for the daily CSV the system already exports, so history matches the same format.
**A5. Drill and permit hooks in rest hours:** the "add a drill's duration to hours of work" offer (spec 13) and the permit job-persons view (spec 14) are written in those modules, but the rules they call live here, so any small additions to `RestHoursService` for them are made in this step to keep the rest-hours code in one place.
Tests: pure tests for the authority rules and retention listing, two-site tests for a deputy signature reaching the office, and the page tests already in place.
